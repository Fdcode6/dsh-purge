# 官方桌面端安装后关闭更新

修改的是安装目录下的 `resources/app-update.yml`，将其改名为 `app-update.yml.disabled-local-repair`，内容和哈希保持不变。Harness 0.2.1-rc.2 在联网检查前检查原文件是否存在，因此重新启动后无法获取内置更新源。

官方 EXE 保持原版，不重新打包或修改数字签名。必须使用本项目入口才能自动执行后处理；单独双击官方 EXE 不带此设置。

## 新安装

运行 `Start-Windows-Setup.cmd` → 菜单 2。安装结束页取消勾选“启动 DeepSeek Harness”。返回菜单后确认安装目录，脚本自动关闭更新源并校验。如果已经启动，完全退出（包括托盘）后再选菜单 6。

若自定义安装路径，请输入实际目录；找不到程序、程序未退出、同时存在两份配置等情况会停止并报告，不会假装成功。

## 已安装

完全退出 Harness 后选菜单 6，或执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows-install\scripts\Disable-Harness-Updates.ps1 -InstallDir "$env:LOCALAPPDATA\Programs\DeepSeek Harness"
```

## 范围与恢复

菜单中的检查更新按钮可能仍存在，点击可能提示缺少更新源。此操作不删除菜单代码、不修改模型服务地址，不停止正常网络功能。无法阻止用户另行运行安装器覆盖升级。重新安装可能恢复更新源，需再次执行菜单 6。

要恢复更新，先退出 Harness，将保留的文件改名回 `app-update.yml`。此设置与插件的在线更新锁独立，两个都需要关闭才能同时保护宿主版本和插件修复。

本机之前已确认改名成功；自动脚本使用临时安装目录验证改名、哈希保持和重复执行。没有在新电脑重新运行整套 GUI 安装。
