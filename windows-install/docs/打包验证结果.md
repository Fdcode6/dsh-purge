# 打包验证结果

验证日期：2026-10-21（北京时间）。材料用于 Windows x64，Python wheel 基线为 CPython 3.13。

## 已验证

- 用户提供的官方 Harness 0.2.1-rc.2 EXE 已移动到 installers；数字签名有效，签名者为 DeepSeek 官方公司。
- Python 3.13.1 安装器签名有效，签名者为 Python Software Foundation；Nmap 安装器签名在前次安装时验证有效。
- Node 26.8.1 ZIP 与官方下载的 SHASUMS256 一致；pnpm 11.25.0 TGZ 与 npm registry 发布的 SHA512 integrity 一致。
- 便携工具保留此前下载的原始包；具备上游校验文件的包此前已逐一核对。suo5 仅有本地下载摘要，不能宣称具备上游签名。
- Python/PowerShell 脚本通过语法检查；下载到的 ZIP 包通过 CRC 完整性检查。
- 使用单独的模拟 desktop profile 和空 pnpm store，`pnpm --offline` 成功安装插件，下载数为 0。
- cwd 修复在模拟 profile 中连续执行两次，支持源目录和 node_modules 为硬链接，不重复追加内容。
- 新建独立虚拟环境，使用 `pip --no-index --no-cache-dir` 从随包 wheel 安装 Impacket 与全部锁定依赖；`pip check` 和模块导入均通过。
- 本次模板快照解压后，通过一个普通检测模板的 Nuclei 语法验证。
- 配置 API 在模拟目录中能识别 15 项路径，显示 ready=true。路径识别不等于可执行性。

fscan、gogo、Chisel 在本次临时目录中出现 Windows `WinError 5 / 拒绝访问`。没有绕过操作系统限制或关闭安全软件；本机最初安装时这些工具的版本/帮助检查曾通过，但不能用旧结果掩盖本次失败。新电脑需要重新验收，自动配置脚本发现任何工具检查失败就停止，不会宣称完成。

测试曾遇到嵌套子进程安装 pip 时 `Bad file descriptor`。将子进程标准输入改为 DEVNULL、输出改为受控管道后，在全新虚拟环境完成安装与检查。保留关闭进度条的参数；不自动重试或忽略真正的安装失败。

## 没有验证或不包含

- 没有在另一台全新 Windows 上完成整套 GUI 安装；本机组件测试不能替代目标机器验收。
- 本次模拟测试的 Nmap/Npcap 使用已安装的本机版本；目标机器仍须运行签名安装器并验证驱动。
- 没有重新触发真实 Harness 的宿主补丁应用，也没有借安装包测试对外扫描。
- 没有包含个人登录凭据、旧会话、FOFA 密钥、VPS 私钥；外部服务和附加技能仍需用户资源。
- manifest.json 保护搬运完整性，本身不是第三方代码签名。校验不符时停止并调查。
