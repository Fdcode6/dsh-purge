# 本地修复版：插件更新已锁定

2026-11-06，本分支关闭 dsh-purge 的内置在线更新机制，防止上游覆盖 cwd 和红队预设兼容修复。

## 锁定范围

- 检测更新：直接返回本地锁定提示，不访问远程版本源。
- 自动更新、在线安装更新、切换通道、切换版本、回退：后端拒绝执行。
- 直接调用更新函数或更新 HTTP 接口，也不能绕过锁定；不会下载、改写插件或触发更新重启。
- 面板仍可能显示原来的更新按钮，点击后提示“本地修复版已锁定插件更新”。不是网络故障。
- 正常应用本地补丁、演练台和普通对话功能不在锁定范围。

这个锁仅覆盖 dsh-purge 自带更新路径，不会禁用 Harness 官方客户端自身升级，也不能阻止外部 AI 助手、包管理器或用户手动替换插件文件。继续使用已验证的 Harness 0.2.1-rc.2；不要把本锁当作整机软件更新策略。

## 安装与生效

新安装：离线安装菜单 4 自动执行 `lock_updates.py`，包括插件源目录和 desktop profile 实际加载目录。

已安装：完全退出 Harness，在仓库根目录执行：

```powershell
py -3.13 .\windows-install\scripts\lock_updates.py "$env:USERPROFILE\.dsh"
```

自定义 DSH_HOME 请替换路径。脚本改动前生成 `update.js.backup-update-lock-*`，兼容硬链接和重复执行；未知代码结构会停止。重新打开 Harness 后生效。若旧进程中已有更新正在进行，请先等待或停止该操作再部署，写磁盘不能撤销内存中的旧逻辑。

## 后续维护

需要新版时，由维护者合并和测试兼容修复，再提供新的离线包。不要通过上游更新按钮覆盖修复版。不要直接把整个含离线材料的仓库安装进插件目录。

若明确需要解除锁定，可退出 Harness 后恢复对应 `update.js.backup-update-lock-*`，但会重新允许上游覆盖修复；不建议日常解除。

## 已验证与边界

`node tests/update-lock.mjs` 覆盖检测、自动、直接安装、通道、版本、更新接口及回退路径：均返回锁定状态；网络访问被测试替身拦截，没有发生网络调用，也没有写入测试 DSH_HOME。红队预设兼容回归测试仍通过。

本次已更新本机实际加载文件，但未替用户重启正在使用的 Harness，未声称新进程 UI 已验证。桌面 ZIP 与远程分支均包含此修复。
